# Artifacts Directory Reference

This document lists the artifact directories generated by local validation
gates, drills, and support tooling, along with their purpose and the
consumers that depend on them. Use this as a stable index when humans,
CI agents, or downstream tooling need to locate and interpret
`artifacts/**` output.

## Validation

- `artifacts/validation/latest_summary.md`, `latest_summary.json` —
  one-page human summary and machine-readable mirror from
  `scripts/validate_local.py`. Always points to the most recent run.
- `artifacts/validation/runs/<UTC-timestamp>/` — full per-gate output
  for a specific run (subdirectories like `python_lint`, `pytest`).
  The directory name is the ISO-style UTC run id used in
  `latest_summary.*`.

## Audit

- `artifacts/audit/FILE_AUDIT_LEDGER.{csv,md}` — per-file inventory with
  tier, size, SHA-256, and lockfile flag. Regenerated by
  `python3 artifacts/audit/gen_full_ledger.py`.
- `artifacts/audit/ISSUE_LEDGER.{csv,md}` — issue register with
  `priority`, `status`, `category`, `file_path`, `evidence`,
  `recommended_fix`, `acceptance_criteria`. Read by the agent workflow
  and by `scripts/validate_local.py` for the P0 regression test.
- `artifacts/audit/ROUTE_INVENTORY.json` and `ROUTE_AUTH_MATRIX.json` —
  regenerated by `scripts/generate_route_inventory.py` and
  `scripts/generate_route_auth_matrix.py`.
- `artifacts/audit/CODE_COMPLEXITY_REPORT.{json,md}` — high-complexity
  function candidates.

## Backup / Restore Drill

- `artifacts/backup_drill/latest_drill.json` — JSON summary of the
  most recent `scripts/backup_and_restore_test.py` run. Contains the
  run id (`runs/<UTC-timestamp>/`), the table row counts before and
  after restore, the produced checksum, the artifact directory under
  `runs/`, and the script exit cause. Downstream tooling (e.g.
  scheduling, dashboards) should treat any non-zero exit, negative
  verification row delta, or missing checksum as a hard failure.
- `artifacts/backup_drill/runs/<UTC-timestamp>/pg_dump.sql.gz` — the
  raw pg_dump captured during the drill. Compressed with gzip.
- `artifacts/backup_drill/runs/<UTC-timestamp>/restore_dump.sql.gz` —
  the dump that was actually applied to the drill container, same
  compression.
- `artifacts/backup_drill/runs/<UTC-timestamp>/drill_log.txt` — full
  stdout/stderr from the drill script for forensic review.

The script always writes the run directory first, then atomically
updates `latest_drill.json` only on success. The presence of
`latest_drill.json` without a fresh `runs/` directory therefore
indicates a stale pointer, not a clean run.

## Alert Delivery Drill

- `artifacts/alert_drill/latest_summary.json` — most-recent delivery
  drill summary. Regenerated by `scripts/run_alert_delivery_drill.py`.

## Benchmark

- `artifacts/benchmark/<UTC-timestamp>/` — per-corpus outputs from
  `scripts/run_benchmark.py` and friends.

## Playwright / E2E

- `test-results/` — Playwright test screenshots, traces, and JUnit
  XML. Re-generated on every E2E run; older entries are safe to
  prune.
- `playwright-report/` — static HTML report. Open `index.html` to
  inspect.

## Logs

- `logs/<UTC-timestamp>.log` — scrollback of long-running processes
  invoked manually (e.g. `scripts/start.sh`).

## Conventions

- All directory names that encode a timestamp use ISO-like UTC
  lexicographic ordering (`YYYYMMDDTHHMMSSZ`), so newest-last
  alphabetical sort also yields chronological.
- A `latest_*` pointer is always updated after the underlying
  `runs/` artifact is durable. Trust `runs/` for forensic detail;
  trust `latest_*` for "is the most recent run healthy?" checks.
