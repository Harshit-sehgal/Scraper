# Agent Instructions

This repository is DataForge Scraper, a pre-production FastAPI +
Playwright web extraction platform for lawful, accessible-web
extraction.

## Truth Source

- Start with `docs/AGENT_TRUTH.md`.
- Treat old audit deliverables, roadmap files, and archived plans as
  historical unless their claims are reproduced by fresh commands in
  the current checkout.
- Use code and command output as source of truth. Do not claim a
  gate passed unless you ran it or can point to a current log
  artifact.
- Local validation logs are written to
  `artifacts/validation/latest_summary.md`,
  `artifacts/validation/latest_summary.json`, and
  `artifacts/validation/runs/`.
- For the per-file audit ledger (stable `ledger_id`, tier, size,
  SHA-256, lockfile flag), use
  `artifacts/audit/FILE_AUDIT_LEDGER.csv` (machine-readable) or
  `artifacts/audit/FILE_AUDIT_LEDGER.md` (human-readable). Both are
  regenerated by `python3 artifacts/audit/gen_full_ledger.py`.
- For doc-vs-code audit, regenerate the truth check with `python3 scripts/verify_docs_match_code.py`.
- For current route visibility, use `docs/ROUTE_INVENTORY.md` and
  `artifacts/audit/ROUTE_INVENTORY.json`; regenerate them with
  `python3 scripts/generate_route_inventory.py`.
- For route auth, middleware, tenant scope, and test coverage, use
  `docs/ROUTE_AUTH_MATRIX.md` and
  `artifacts/audit/ROUTE_AUTH_MATRIX.json`; regenerate them with
  `python3 scripts/generate_route_auth_matrix.py`.
- For the stable product boundary versus experimental/research code,
  read `docs/STABLE_VS_EXPERIMENTAL.md`.

## Agent Contract — 12 rules

1. **Run baseline validation first.** Before any non-trivial edit,
   run `python3 scripts/validate_local.py --quick`, then run the
   targeted tests for the files you will touch. See
   `docs/VALIDATION.md` and `docs/AGENT_TRUTH.md` for current command
   evidence.
2. **Do not trust old status docs blindly.** Treat any project
   `*_STATUS.md` / `*_READINESS.md` / `ROADMAP.md` /
   `MASTER_PLAN.md` file as historical; numbers and confirmations
   in them are not reproducible in the current checkout. Anchored
   evidence lives in `docs/AGENT_TRUTH.md` and the CMD output it
   references.
3. **Use code and command output as source of truth.** If a doc
   says a gate passed but the command does not reproduce, the doc
   is stale. Update the doc or remove the claim.
4. **Do not hallucinate issues.** If you cannot point to a file
   path, a line, a command, or a log artifact, do not assert the
   issue exists.
5. **Inspect project-owned files before editing.** Use
   `artifacts/audit/FILE_AUDIT_LEDGER.md` to find the relevant
   files, and read them in full before proposing a change.
6. **Write tests before fixing important bugs.** For any P0 / P1
   change, add a failing test in the appropriate `backend/tests/`
   file first, confirm it fails, then fix the code.
7. **Keep auth centralized.** All authentication and authorization
   must go through `app.utils.rbac.resolve_auth_context` and the
   `require_principal` / `require_role` dependencies. Do not roll
   a new auth check inline in a router.
8. **Enforce tenant / user / project isolation.** Before returning
   jobs, results, events, exports, recycle-bin items, audit logs,
   or billing records, perform an explicit owner / org / project
   check. Admin / operator all-access must be opt-in and tested.
9. **Do not mix experimental / research code into stable product
   paths.** Research modules live under `backend/app/research/`
   and are gated by `DATAFORGE_ENABLE_EXPERIMENTAL_ROUTES`. The
   gate is enforced at three levels (registry, lifespan, router
   mount). The boundary is asserted by
   `scripts/check_research_boundary.py` and
   `backend/tests/test_research_kernel_boundary_invariant.py`.
   See `docs/STABLE_VS_EXPERIMENTAL.md` before changing this
   boundary.
10. **Do not add unsafe scraping / bypass behavior.** No CAPTCHA
    bypass, no anti-bot bypass, no paywall bypass, no login bypass,
    no brute-forcing session IDs, no scraping private /
    unauthorized systems, no unsafe cookie / token handling.
11. **Record all command evidence.** Append the actual command, the
    actual exit code, and the actual output (or first/last lines)
    to `docs/AGENT_TRUTH.md` or `artifacts/audit/VALIDATION_REPORT.md`
    so the next agent can reproduce.
12. **Keep changes focused and reviewable.** One change, one
    purpose. Smallest diff that solves the user's problem. Do not
    reformat unrelated code, do not refactor as a side effect, do
    not add new dependencies casually.

## P0 Safety Rules

- Add failing tests before changing P0 behavior.
- Keep authentication centralized through `app.utils.rbac.resolve_auth_context`.
- Enforce tenant isolation through explicit owner / org / project
  checks before returning jobs, results, events, exports,
  recycle-bin items, audit logs, or billing records.
- Misconfigured API auth must fail closed. `/api/*` routes are
  protected unless intentionally exempt.
- Preserve product safety: do not add CAPTCHA bypass, anti-bot
  bypass, paywall bypass, private-system scraping, login-protected
  scraping, or unauthorized access features.
- Do not edit experimental / research modules unless the task
  directly requires it.

## Production Claims

Do not call this project production-ready or 100/100 SaaS-ready
unless staging deployment, TLS, secrets, backups, restore drill,
monitoring, alerting, load tests, auth, tenant isolation,
billing / usage enforcement, benchmark gates, and incident runbooks
are proven in the current checkout and target environment.
