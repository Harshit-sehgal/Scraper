## Current Architecture Summary

The stable application is a FastAPI backend with a static internal frontend. `backend/app/main.py` composes middleware, static mounts, routers, lifespan, and experimental route gating. The route inventory records 124 registered routes, 89 stable and 35 experimental. The route auth matrix records 114 API routes, 0 unknown auth rows, and 1 unknown tenant-scope row: `GET /api/saas/plan`.

The core scraping flow is mostly split into services:

- `backend/app/services/job_runner.py` orchestrates discovery, scraping, AI structuring, post-processing, insight, and finalization.
- `backend/app/services/status_classifier.py` classifies terminal job states.
- `backend/app/services/finalization.py` handles terminal cost/status/offload/persistence behavior.
- `backend/app/scraper.py` remains the generic scraping entry point and delegates to extractor, telemetry, provenance, crawl policy, and adaptive hook modules.

The system is safer than a single monolithic router, but several large functions and mixed responsibilities remain. These should be refactored only behind characterization tests.

## Target Architecture

Preferred boundaries for future work:

- Routers: HTTP request/response, dependency injection, status codes only.
- Services: business workflow and policy orchestration.
- Repositories: storage access and transaction boundaries only.
- Schemas: API request/response models.
- Domain: state machines, authorization policies, and value objects.
- Utils: pure helpers with no hidden I/O.
